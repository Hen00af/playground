# socket programming
## 目標
昨今、当たり前に使われているネットワークだが、その本質は複数の層によって抽象化されたバイト列である。
そのバイト列をどのようにピアツーピアでやり取りしているのかを理解するのが本章の目標である。

### TCPバイトストリームとプロトコル

ピア（プロセス）同士が通信を行う際、ネットワークでそれらを接続し、バイトのやり取りを行うものという理解になりがちです。
しかし、最も一般的なプロトコルであるTCPはバイトを生成するわけではありません。
実際には内部境界のないTCPバイトストリームを生成します。

そのバイトストリームをいかに解釈するかを記述するのがアプリケーションプロトコルの役割であり、バイトストリームを意味のあるバイトにどうやって分割するのかなどの、バイトストリームを理解するためのルールを定めています。

### データのシリアル化について
ネットワーク経由で送信したいものは主に
- 文字列
- 構造体
- リスト

などの高レベルオブジェクトになりがちですが、受け取ることができる情報はバイトのみです。
そのため、byte to objectまたはobject to byteの変換をしなくてはなりません。
これはそれぞれ、decerealization(非連続化)またはcerealization(連続化)と言います。

### 非同期処理について
プロトコル処理があればクライアントアプリケーションは簡単に作成できます。（プロトコルによって成形された情報をexecutionすればいいだけなので。）が、サーバー側は複数のクライアントへの接続を行うので処理が複雑になります。
多数の接続を伴うサーバを管理することは従来から困難でした（C10K問題）。

現代のハードウェアに関しては性能が向上してはいますが、その性能を最大限活かすためのソフトウェアがが必要不可欠です。

現代の、この問題に関するソフトウェアソリューションはイベントループを使用したインベントベースの並行処理であり、nginx, go lang, redisbなどの、最新のスケーラブルなソフトウェアを支えています。
